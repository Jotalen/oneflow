# NextMove Implementation Plan — HackUTD 2026

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, single session; hackathon clock forbids per-task subagent review). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship NextMove, a Nessie v2 banking dashboard that shows one person's full financial picture, folds in their Toyota loan/lease, ranks the next best moves by 24-month dollar impact, explains via LLM that never computes, and executes accepted moves in the bank, by 12:00 PM CST Sun Nov 8 2026.

**Architecture:** One Next.js (App Router, TS) process. Browser never touches Nessie directly; a server proxy at `/api/nessie/*` holds the bearer key and a token-bucket rate limiter. Toyota CSVs are read server-side. A pure-TS engine (`src/lib/engine`) turns a normalized `Profile` into health indicators, a 24-month projection, and ranked `Move`s. LLM sits behind a provider interface with a deterministic stub. App state lives in localStorage + committed JSON snapshots; Nessie is the system of record for bank data.

**Tech Stack:** Next.js 15, TypeScript strict, Tailwind, Recharts, Vitest, papaparse, zod, Gemini API (`@google/generative-ai`), Docker + Caddy on Vultr.

**Spec:** `~/Downloads/HACKUTD_2026_CONTEXT.md` → copied to repo as `docs/HACKUTD_2026_CONTEXT.md`. Toyota pack → `data/toyota/`.

## Devil's Advocate

### On the decisions

**D1 Time budget / sleep.** 17 coding hours against ~19h of listed work. The lie everyone tells is "I'll be faster at 3am." You won't. Mitigation: checkpoints are hard gates with pre-decided cuts; sleep block is non-negotiable (bugs after 20h awake cost more than 3h). Deploy before sleep so DNS and Docker pulls happen while you're out.

**D2 TS-only.** You rewrite amortization, lease math, 8 metrics, Markov (stretch) by hand with no numpy and no PNC code. Risk: subtle math bugs judges spot (DTI off by 100×). Mitigation: Vitest fixtures with hand-computed expected values from `option_scenarios.csv` (e.g., C001 REFI `new_monthly_payment` must be reproduced within $1 by `amortize()`); PNC parity doc maps each metric to their definition.

**D3 Gemini + stub.** Gemini free tier is 15 RPM; judges mashing "AI analyze" → 429 mid-pitch. Function-calling flakiness on Flash is real. Mitigation: stub is first-class, produces a templated brief from engine output, and the UI shows a provider chip ("Gemini" / "Offline narrator"). Flip to stub with one env var. Never demo on live Gemini without rehearsing stub.

**D4a Fraud tile.** Simulator customers are strangers; a judge asks "whose fraud is this?" Mitigation: tile titled "Bank-wide fraud monitor", subtitle "5 simulated customers, 2,000 transactions, nothing labeled — our detectors found N". Rules are transparent and listed on expand. Detector thresholds are constants in one file.

**D4b Pending guard.** Non-card transactions settle in ~10s; by the time a 2s poll + rules + UI render happen, the window may close. Mitigation: demo with credit-card purchase (60s window); UI treats "already settled" as a non-error. Webhook upgrade only if deployed; otherwise `decision_source=owner` and you say "the app decided" honestly.

**D4c What-if 1h max.** Sliders re-run `project()` on every change; 24 months × ~6 accounts is microseconds, fine. Risk is UI time, not compute. Mitigation: two sliders only (extra $/mo to top debt, new monthly income), debounced 150ms, reuse Two Futures chart component.

### On the features

**F1 Seed.** 20 personas × ~60 calls = ~1,200 calls = 10+ minutes at the cap, and any 5xx mid-run leaves half a persona. Mitigation: seed is per-persona, resumable (writes `seed-ids.json` after every resource), `--persona C003` flag, 3 priority personas first, rest in background. Shared merchants created once. Reset deletes by stored ids. Never run seed during demo (shared rate budget).

**F2 Your Picture.** PNC lists CDs/IRAs/mortgage; Nessie has none and no persona has a mortgage. Empty groups look like gaps. Mitigation: groups render only when non-empty (tile rule), README states Nessie's type model, and C005/C020 get a "CD 12mo" savings account so the group appears for at least two personas.

**F3 Next Moves.** Car moves come from a CSV, bank moves from rules; mixing precomputed `total_cost_vs_keep_as_is` with projected net-worth delta is apples/oranges. Mitigation: ranking key is always `impact24 = netWorth24(applied) − netWorth24(base)`; car options are *applied* to the profile (payment change, upfront cost, payoff) and projected like any move; the CSV's own total is shown as "TFS estimate" beside ours. Golden badge requires id match AND eligibility Y.

**F4 Two Futures.** Two lines that look the same for small moves (DUEDATE saves $0 in net worth but avoids overdraft fees). Mitigation: moves can declare `impactKind: 'netWorth' | 'fees' | 'risk'`; chart annotates events; card shows the right metric ("−$140/yr in overdraft fees").

**F5 Execute.** A Nessie transfer is pending for ~10s; if you re-fetch immediately, balances show a hold, not the final. Mitigation: after POST, optimistic UI applies the move locally, poller watches for `transaction.completed` with matching `tx_id`, then re-fetch + re-project. On any Nessie error, keep cached profile, show badge.

**F6 Coach.** Tool loop can spiral (model calls `run_projection` 6 times). Mitigation: max 4 tool calls per turn, then force a text answer; tools are idempotent and cheap; system prompt includes the Toyota starter rules verbatim plus "You may not add, subtract, multiply, or divide; quote numbers from tool results."

**F7 TFS toggle.** Expected value = `value_if_completed_usd × assumed_take_rate` is already in `golden_answers.csv`; recomputing invites mismatch. Mitigation: display their columns directly; compute nothing new. Toggle is a view, 45 min.

### System-design issues raised and resolved

- **Two data owners for one truth:** Toyota CSV says monthly payment $412; Nessie loan says `monthly_payment_cents` 41200 because we seeded it from the CSV. If anyone edits one, they drift. Resolution: CSV is the source for car/contract fields; Nessie loan is a mirror created by seed; normalizer reads car fields from CSV, bank fields from Nessie, never cross-checks.
- **Circular spending baseline:** see Assumption 8. Resolution: say it plainly; judges respect honesty over fake realism.
- **Time semantics:** Nessie `created_at` for seeded deposits is "now", not 8 weeks ago (no backdating in API). Resolution: normalizer derives paycheck cadence from the Toyota `payday_day` + `annual_income`, not from Nessie timestamps; Nessie deposits exist for balance realism and the transaction list.
- **Idempotency:** re-running seed duplicates customers. Resolution: seed checks `seed-ids.json` and skips existing persona unless `--force`.

## Data Flow

**Read path:** `GET /api/profile/C003` → server loads Toyota rows (cached) + `seed-ids.json[C003]` → parallel Nessie: customer, accounts, each account's transactions (limit 200), bills, loans → `buildProfile()` merges: bank fields from Nessie (balances, cards, bills, recent txns), car + contract + options from Toyota CSV, income/payday from Toyota customer → `Profile` → client `useProfile` caches to localStorage `nm:profile:C003` → `health()`, `project()`, `rankMoves()` run client-side (pure TS, no secrets) → UI.

**Execute path:** MoveCard "Accept" → `POST /api/execute {persona, moveId}` → server rebuilds Profile, `planExecution(move)` → ordered Nessie ops (e.g. `transfer checking→savings amount_cents`, or `createBill status:recurring recurring_date:payday`) → returns `{ok, txIds[]}` → client applies optimistic move → `useEventFeed` sees `transaction.completed` for a `tx_id` in `txIds` → re-fetch profile → re-project → chart animates from old to new series.

**Guard path:** poller receives `transaction.pending` → `PendingGuard` lists it → `guardDecision()` → auto `POST /api/decide` unless rule says "ask" → user override buttons → `decision_source` shown.

**Fraud path:** H0 `scripts/simulate.ts` → `data/sim-ids.json` → `FraudTile` server route pulls transactions for sim accounts (newest first, limit 500 each) → `detectAnomalies()` → list with rule name + evidence.

**Offline path:** any `/api/profile` failure → `useProfile` loads `localStorage` → else `/snapshots/C003.json` (served statically from `public/snapshots`, copied from `data/snapshots` at build) → badge "offline snapshot".

## Nessie v2 Endpoints by Feature

| Feature | Endpoints |
|---|---|
| Seed (F1) | `POST /customers`, `POST /customers/{id}/accounts` (Checking, Savings, Credit Card), `POST /accounts/{id}/deposits` ×8, `POST /merchants` (12 shared, once), `POST /accounts/{id}/purchases` ×~40, `POST /accounts/{id}/bills` (status `recurring`, `recurring_date`, `payment_amount` dollars), `POST /accounts/{id}/loans` (`type`, `status`, `credit_score` from tier, `monthly_payment_cents`, `amount_cents`, `description`) |
| Reset | `DELETE /bills/{id}`, `DELETE /loans/{id}`, `DELETE /accounts/{id}`, `DELETE /customers/{id}` (reverse order) |
| Picture (F2) | `GET /customers/{id}`, `GET /customers/{id}/accounts`, `GET /accounts/{id}/transactions?limit=200`, `GET /accounts/{id}/bills`, `GET /accounts/{id}/loans` |
| Execute (F5) | `POST /accounts/{id}/transfers {payee_id, amount_cents, description}`; extra principal = transfer to loan-linked account + `PATCH /loans/{id}` not available → model extra principal as transfer checking→savings nicknamed "Loan principal" + local debt reduction (README notes Nessie has no loan-payment endpoint); autopay = `POST /accounts/{id}/bills {status:'recurring', payee, payment_amount, recurring_date}`; cancel recurring = `PATCH /bills/{id} {status:'cancelled'}` |
| Events (F5, guard) | `GET /events?after=&types=transaction.pending,transaction.completed,transaction.declined&limit=100` |
| Guard | `POST /transactions/{id}/decision {decision:'approve'|'decline', reason}`; dev button: `POST /accounts/{cardId}/purchases` |
| Fraud | `POST /simulations {mode:'historical', customers:5, transactions:2000, anomaly_rate:0.08, seed:42}`, `GET /simulations/{id}` (poll until `finished`, read `account_ids`), `GET /accounts/{id}/transactions?limit=500` |
| Webhook (conditional) | `POST /webhooks {mode:'decision', url, kinds:['purchase'], on_error:'approve', max_wait_seconds:30}`; verify `Nessie-Signature` HMAC-SHA256(timestamp + body); de-dupe `Nessie-Event-Id` |

**Rate-limit strategy:** `client.ts` token bucket 120/min with burst 30; queue when empty; on 429 sleep `Retry-After` (fallback 2s, ×2, cap 30s) then retry once; typed `NessieError {status, retryAfter}`. Seed throttles to 100/min to leave headroom. One poller in the app (`useEventFeed`, module-level singleton) at 2s; on 429 or empty page with `Retry-After`, honor it. Never run seed during the demo.
